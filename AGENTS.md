# Правила работы над HW2

## Проект и ограничения задания

- Рабочий проект: `/Users/hadhad/HSE/NLP/HW2/NLP_HW2`. Сохраняй структуру
  PyTorch-шаблона: `src/`, конфиги Hydra, `train.py`, `inference.py`.
- Журналы и `run.ipynb` находятся в корне проекта. Скачанные данные находятся
  в `../data`; не переноси и не скачивай их заново без необходимости.
- Модель: Transformer с энкодером и декодером, обучение с нуля.
- Используй только предоставленный датасет `SlavaYus/tinysms_qa_12m`.
  Дополнительные обучающие данные и таргеты, включая дистилляцию, запрещены.
- Генерация всей тестовой выборки должна занимать не больше 180 секунд на
  одной NVIDIA T4. Результат замера на другом оборудовании не подтверждает
  выполнение этого ограничения.
- Для сдачи нужны весь код, объяснённый ноутбук инференса и PDF-отчёт.
  В отчёте требуется описать использование агентов и все эксперименты.
- Решения от 2026-10-23: обучение через Kaggle API на двух T4, бюджет одного
  запуска до 4 часов; validation_fraction=0.001 стабильным hash по question.
  Comet: workspace `had-a42`, project `NLP_HW2`. Kaggle username
  `andrewkhoroshilov` предварительный, его ещё нужно подтвердить перед отправкой.
- Посылка: только JSONL, один объект с единственным полем `code` на задачу,
  в исходном порядке. Рекомендованный предел генерации — 64 токена по умолчанию.
  Метаданные и row_id сохраняй отдельно от посылки.
- Квантизация, дистилляция и другие методы сжатия отложены пользователем.
- Текущее решение по batching: train/val используют динамический бюджет
  16 384 padded source+target токена на GPU, max_batch_size=256,
  bucket_size=3200 на rank, accumulation_steps=2. Количество задач переменное;
  не описывай батч как фиксированные 128 задач. Фиксированные батчи доступны
  только в контрольных experiments=fixed_batches/bucketed.
- Следующий подготовленный запуск (2026-10-24): experiments=pre768_3epochs,
  Pre-LN, d_model=768, heads=12, FFN=1920, 4E/4D, layer_repeats=1.
  Пользователь выбрал цель 3 эпохи; затем явно поручил запуск и снял
  ограничение времени обучения. trainer.max_hours=null, лимит launcher
  отключён; внешние ограничения Kaggle сохраняются. Scheduler рассчитывается
  по фактическим планам эпох. Актуальный пакет: kaggle/build/pre768-unlimited.
  Инференс: greedy/beam=2/4, лимиты 64/128, каждый вариант должен пройти
  полный отдельный замер <=180 секунд на одной T4.
- Финальный выбор пользователя: beam=4, max_new_tokens=128, batch_size=32,
  length_penalty=0.6, FP16/static KV-cache. Public pass@1=73.54% по сообщению
  пользователя; два внешних T4 замера 58.234157/57.838530 с. Итоговый файл:
  predictions-final-beam4-128.jsonl. Широкий beam-перебор завершён; не
  считать прежний beam=16 финальным выбором. Полное воспроизведение — README.md.

## Эксперименты

- Веди [EXPERIMENTS.md](EXPERIMENTS.md). Один эксперимент — один полный
  завершённый запуск обучения и предусмотренной для него оценки.
- До запуска опиши цель, гипотезу, критерий успеха и отличие от предыдущего
  запуска. По возможности меняй один фактор за эксперимент.
- Каждый полный запуск получает отдельный ID `EXP-001`, `EXP-002` и далее.
  Повтор с другим seed или конфигом тоже получает отдельный ID.
- Сохраняй ссылки на фактический полный конфиг, исходные конфиги, команду с
  overrides, описание архитектуры и изменение относительно предыдущего запуска.
- Записывай данные, токенизатор, seed, оборудование, бюджет обучения, ссылку
  на Comet, checkpoint и реально полученные метрики по шаблону журнала.
- Разрешённый Hydra-конфиг и overrides фиксируй для конкретного запуска:
  ссылка только на изменяемый общий конфиг недостаточна.
- Прерванные запуски, ошибки, smoke-проверки и переобучение на одном батче
  записывай в отдельный раздел технических запусков.
- Неизмеренные значения помечай «не измерено». Validation loss и токенная
  accuracy не заменяют pass@1. Результаты бота записывай с указанием public
  или private части.
